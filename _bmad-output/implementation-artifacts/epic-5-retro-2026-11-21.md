### Integrity (FR-17) and the cvEntries boundary

8. **All four Fixture CVs have no blank lines, so `cvEntries` returns the whole CV as one entry.** `grep -c '^\s*$'` on each `cv.txt` is 0. The FR-17 Upgrade check asks whether the *cited CV entry* has the Upgrade word; for these CVs that becomes "the Upgrade word is anywhere in the CV". A pasted CV from a PDF often has single line breaks only, so the same happens for a Student. The guard still works when the CV never uses the word (nursing: no «forsket»), but the exam-paper-versus-research distinction the story is about rests on blank lines being there. FR-15 and the Letter check (4.5) use the same splitter. Source: `data/fixtures/*/cv.txt`; `src/modules/integrity/core/cv-entries.ts`; `spec-5-2-…md` deferred. Severity medium. Disposition: **fix now (proposed)**: decide how an entry is bounded when the CV has no blank lines (for example a window of lines around the citation), keeping one splitter. This is a spec decision for Helene before code. Prevention: a Fixture or planted CV with entries on single-newline text, so the boundary is tested on the shape the real input has.
