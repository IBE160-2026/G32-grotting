## Findings

### Spec-to-implementation reconciliation

1. **FR-22 says «keyword lists» are encrypted; the shared `keyword_lists` table is plain.** The PRD (FR-22, `prd.md:465`) lists «keyword lists» among the encrypted fields. The architecture decided that this means the `analysis` column (encrypted: `src/modules/application/server/schema.ts:29`), and the shared `keyword_lists` table stays plain: the AI-proposed words of a Job ad, saved under the hash of the ad, with no Student id and no CV, every word standing in the ad. `test/fr22-raw-rows.test.ts:34–41` states the decision and checks exactly that (its columns, its hash, and that each word is in the ad). The words of an ad are the same words the app takes from public text, but the PRD wording and the table disagree. Disposition: **spec reconciliation (proposed)**: Helene decides to reword FR-22 («the keyword list of an Application», not the shared hash-keyed store) or to encrypt the table; the first is the simpler and matches the architecture. Fits Story 7.5. Source: `prd.md:465`; `fr22-raw-rows.test.ts:34–41`; `issues.md` line 368. Prevention: when architecture narrows a PRD field list, the PRD line is changed in the same step.
2. **The Hosted default is decided in two places in `config.ts`.** The AC said `FEATURE_DEFAULTS.accounts = true` is the only place that switches accounts on. 6.12 did that and added `hosted ? false : FEATURE_DEFAULTS.accounts` in `parseConfig` (`config.ts`, in the `accounts` line), because a plain flip would have turned accounts on in a Hosted redeploy without `ENCRYPTION_KEY`. Documented in the spec and in `issues.md`. Disposition: **accept** (the better reading of the goal: «must not be able to switch accounts on on Hosted»). The older `issues.md` line 360 («a redeploy of Hosted gets accounts on») is partly out of date and should be reworded for the 3 December decision (action item 7). Source: `config.ts` diff in `3ea0905`; `spec-6-12-…md`; `test/accounts-default.test.ts`.
3. **ACs 6.1–6.12 are met in the evidence.** Encryption at rest of the listed fields (`crypto.ts`, the encrypted column types, `fr22-raw-rows.test.ts` with a positive control that fails when the CV is stored in plain: spec 6.12 mutation check), per-Student scoping (every repository read in `repository.ts` is by `(id, studentId)` or `studentId`: 28 uses; `fr19-privacy.test.ts`; mutation check: dropping the student filter fails five FR-19 tests), the 30-minute session and the two-minute warning (6.5), Profil CV (6.3, 6.6), automatic save with `JA-NNN` (6.7), Historikk and reopen (6.8, 6.9), Konto and logout (6.10), the seed user (6.11), the default switch (6.12). Checked and clean. Source: the twelve specs; `git show 3ea0905 --stat`.
4. **`saved-contracts.ts` breaks the `contracts.ts` convention.** The stored-Application schema lives in `src/modules/application/saved-contracts.ts` because `contracts.ts` would form an import cycle with `letter/contracts` and `gaps/contracts` (spec 6.9). Disposition: **accept**; note it for Story 7.5 or the architecture doc so the next agent does not «fix» it back.
5. **Two choices the AC text did not make, both recorded in `issues.md`:** the navigation item «Katalog» on Konto shows the count («2 søknader»), not the range «JA-001–JA-002» of the mock; and the «Kopier brev» button name is «Kopier brev for JA-002», not the UX text «Kopier brevet til JA-002», because axe (`label-content-name-mismatch`) needs the visible word in the name. Disposition: **accept**, and correct `EXPERIENCE.md` (Story 7.5). Source: `issues.md` 6.8 and 6.10 choice lines.

### Integrity, privacy and what is stored

6. **Corrected 2026-11-25 (after the retro): the Student pages already answer with `Cache-Control: no-store`.** The retro first read a `grep` for `no-store` in `src` (which finds only the API routes) as «the pages have none». That was wrong: Next sets `no-store` itself on dynamic pages, and every Student page is dynamic (`connection()` or the session read). The new `e2e/student-pages-cache.spec.ts` shows it: `/soknad`, `/profil`, `/historikk` and `/konto` each answer with a `Cache-Control` that contains `no-store`, and Back after «Logg ut» from Historikk (Konto is replaced in the history by the full load of Hjem) asks the server again and ends on Logg inn with no Student content. The bfcache worry of 6.10 and 6.12 is therefore covered; what was missing was a test that pins it. Disposition: **closed by the regression test** (this fix). Source: `e2e/student-pages-cache.spec.ts` (5 passed). Prevention: before calling something missing, check the response, not only the source.
7. **A failed phase-2 write is logged, not shown.** 6.7: after phase 1 saves the row the Student sees «Lagret i Historikk som JA-001.»; if the later Letter, Gaps or check write fails, the code logs and moves on, so the saved sentence is true of the Application but the reopened entry can say «Ikke laget.». Also a resubmitted Gap analysis that fails keeps the old `gaps_rev`, so that check is not stored. Source: `spec-6-7-…md` Residual risks. Disposition: **defer**; it needs a database failure in the second request to happen, and the entry is honest when reopened. Record as an accepted limit in the README or the architecture doc (Story 7.5).
8. **Unsalted `fingerprint` and plain `keyword_lists` are plain by decision.** `fingerprint` is an unsalted sha256, plain by AC; `keyword_lists` see finding 1. Disposition: **accept**.
9. **Deferred security items, all kept out of the AC and judged in 6.12:** no AAD (ciphertext not bound to row and column), no rate limiting or lockout on login and register, no tab synchronisation of the session, no CV deletion in Profil, no test that proves equal scrypt time for known and unknown email, bfcache (finding 6). Source: `issues.md` lines 290, 292, 302, 320, 357; the 6.12 assessment line 373. Disposition: **accept** for AAD, rate limiting and tab synchronisation in a course project with the Hosted version frozen; **defer** the equal-time test (low); bfcache is covered (finding 6). Rate limiting becomes relevant only if accounts are ever switched on Hosted (3 December decision).
