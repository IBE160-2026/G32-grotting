- (decision) Sources confirmed: both brief.md and addendum.md from brief-JobAssistant-2026-09-11 inherited by reference.
- (decision) Platform: web app (confirmed from brief, no change).
- (decision) Competitor reaction: dislikes Teal's UI; likes Kickresume's pattern of surfacing the 'start your application' action prominently at the front of the page (not buried).
- (decision) Color direction: black background with white text (dark theme, high contrast).
- (decision) Navigation: top navbar with buttons that stay visible/pinned even as the navbar collapses (persistent key actions vs. a fully collapsing hamburger-only nav).
- (decision) Navbar mechanic: on mobile/narrow screens nav links collapse into a hamburger menu, but the key CTA button stays outside the hamburger and always visible.
- (decision) Typography/brand mood: professional and sharp (not playful/colorful like Kickresume).
- (decision) Responsive: must work well on phone browser (no native mobile app per brief scope, but web must be responsive). Dark mode only, no light mode toggle.
- (decision) Key journey (protagonist Violet, first session): Home screen (list of applications) with big 'Create tailored application' CTA -> signup (username/email/password) -> Profile page (CV upload + personal info) -> back to Home CTA OR navbar 'Application' link -> paste job description page -> generates tailored CV + application letter + reflection note (gaps + ATS-screening explanation) -> user manually adjusts output -> separate 'Review CV' button (upload CV, get feedback doc) and 'Review application' button (upload application, get feedback doc).
- (decision) Color theme picked: Violet Precision (technical/precise register, indigo-violet #8B7CF6 accent, near-black #0A0A0A background, #F5F5F5 text) from color-themes-1.html.
- (decision) Output editing: generated CV/application is downloaded and edited externally (not an in-app editor).
- (decision) Navbar reachable items: Home, Application, Profile, History, Account, Logout.
- (decision) Review CV / Review application are standalone features, reachable anytime (not only right after generating a new application).
- (decision) Generated output delivered as a downloadable file (not shown/edited in-browser).
- (decision) Navbar final: flat six buttons (Home, Application, Profile, History, Account, Logout); Home and Application rendered bold/emphasized as primary actions.
- (decision) Review CV / Review application entry points: accessible from Home screen (not a separate navbar item).
- (decision) Working mode: fast path selected for remaining detail (component styling, microcopy tone, accessibility, state/error handling) - draft with [ASSUMPTION] tags for user review.
- (decision) All 9 fast-path [ASSUMPTION] items in DESIGN.md/EXPERIENCE.md confirmed as-is by user: Login page (email+password), mobile persistent CTA routes to Application flow, Home=recent vs History=full archive, inherited typography/shape scale, dedicated error/red color, ATS match threshold placeholder >=70%, standalone Review feedback doc has no score/chips, encrypted-storage trust microcopy near uploads/Account, Account page fields (password change + data note).
- (change) Mobile-nav feedback from key-mobile-nav.html mock: persistent CTA in collapsed navbar was too crowded. Fixed by shortening label to 'Create application' (was 'Create tailored application') and rendering it compact (body-sm text, smaller padding) vs the full-size button-primary style, for the mobile persistent-CTA context only; Home's full-size CTA keeps the full label.
- (event) Exploring a beige/light color palette as a preview-only comparison against the confirmed dark Violet Precision theme; not a committed change yet.
- (override) REVERSAL: abandoning the dark theme (black bg, Violet Precision accent, dark-mode-only) in favor of the light beige 'Warm Editorial' palette, with a pink accent instead of Warm Editorial's original terracotta/orange. This also reopens the 'professional and sharp, not playful/warm' mood decision -- new direction leans warm/editorial/human. Reason: user preview comparison, explicit preference for beige+pink over dark.
- (event) Also exploring a brown/mocha accent (light caramel vs. deeper mocha/espresso) on the same beige base, as an alternative to pink, before final accent decision.
- (decision) FINAL color/theme decision: beige 'Warm Editorial' light theme (bg #F2E4CF, surface #FAF1E1, text #3A2A1D, text-secondary #8A7157, border #E0CBA8) with 'Rich Mocha' brown accent (#6B4226, accent-strong #96603A), success green #4C7A3F, warning goldenrod #B8860B, error red #A8341F, from .working/color-themes-4.html. This fully replaces the earlier dark Violet Precision theme and the 'dark mode only' decision -- JobAssistant is now a single light theme, no dark mode. Brand mood shifts from 'professional and sharp/technical/clinical' to warm/editorial/human, per the Warm Editorial register the user picked.
- (decision) Review CV / Review application buttons on Home should be colored (not plain outline/secondary), using a lighter brown fill than the primary CTA. Implemented as new 'button-review' component: {colors.accent-strong} fill (#96603A) vs primary's {colors.accent} (#6B4226), same accent-text foreground.
- (decision) Final accent hex refinement (user-specified exact values): accent (primary 'Create tailored application' button) = #7F6244, accent-strong (review buttons) = #937A62. Slightly lighter/more neutral than color-themes-4.html's original Rich Mocha (#6B4226/#96603A). Contrast note: accent-strong vs accent-text (#FFF6EE) is ~3.8:1 -- passes AA for large/bold UI text and component boundaries (3:1) but is under the 4.5:1 normal-text AA threshold; flagged in DESIGN.md for follow-up if needed.
