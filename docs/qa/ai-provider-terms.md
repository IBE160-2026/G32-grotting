# AI provider terms: the Bake-off contenders

Story 3.3 (PRD §8.1, Open question 3); the contenders were Anthropic and OpenAI directly, then OpenRouter (Stories 3.3b and 3.3c); the decision is in the Decision section below (Story 3.3d). Checked on **2026-11-18** from the providers' own public pages, by Claude while building the story. **Helene has confirmed only the rows that say so** (OpenRouter dashboard settings, 2026-11-18 and 2026-11-19; the DPF search for Anthropic and OpenAI, 2026-11-18). A fact that was not read on a primary source says «not verified»; look at those yourself (step 2 in `docs/qa/bake-off-runbook.md`, now a condition for Story 3.12).

PRD §8.1 asks for: a paid or commercial API tier only, a written promise of no training on inputs, a documented retention period (named in the AI notice), a data processing agreement, and processing in the EEA or a provider on the EU–US Data Privacy Framework (DPF) list.

## Decision

**Decided 2026-11-18 (Helene, Story 3.3d):** Claude Sonnet 5.5 (`anthropic/claude-sonnet-5.5`) used through OpenRouter, not directly. See `docs/architecture.md` section 4 and PRD Open question 3. The Student's text therefore reaches OpenRouter and the model's host: under `zdr: true` only Google Vertex and Amazon Bedrock serve this model, so the host is Google or Amazon, not Anthropic (the host that served the bake-off requests was Google Vertex, reported by Helene on 2026-11-19; see «Which host serves the request»). The OpenRouter rows below, and the host's retention under the `zdr` routing the app asks for, are **not verified** and are a condition for Story 3.12 and the AI notice (Story 3.6). The Anthropic and OpenAI tables below are kept as the record of what was compared; the direct packages are removed from the code.

## OpenRouter (`@openrouter/ai-sdk-provider`)

Added in Story 3.3b; 3.3c lets the run compare several models through the one key, each its own contender. Checked on **2026-11-18** from OpenRouter's public docs by Claude. **Helene has confirmed only the rows that say so** (the monthly limit and ZDR only in the dashboard, and the DPF search for Anthropic and OpenAI); every other row was read by Claude and is not confirmed by Helene. OpenRouter is a **router**: one key and one API in front of many model vendors. The Student's text therefore reaches **two companies**: OpenRouter, and the vendor whose model answers (a second processor, with its own terms, retention and country). Every row below that is about the model vendor depends on which model and which endpoint OpenRouter picks, so it cannot be answered once for «OpenRouter».

What the adapter asks for on every request (the `provider` object of the request body, see `OPENROUTER_PRIVACY` in `src/modules/ai/server/adapters/live.ts`): `data_collection: "deny"` (only providers that do not collect user data) and `zdr: true` (only Zero Data Retention endpoints). Both field names are in the package's types and in OpenRouter's provider routing docs.

**AI notice (Story 3.6, built 2026-11-19):** OpenRouter won (see Decision), so the notice names **both** OpenRouter and the host: «OpenRouter, en mellomtjeneste som sender dem videre til Google (Vertex AI) eller Amazon (Bedrock)», and not Anthropic (see «Which host serves the request»). It names two hosts because the requests are **not pinned** (`provider.only` is not set; the adapter has no setting for it, and a wrong provider slug would switch live AI off on a request nobody can test without a paid call, so it was left out). If a host is ever pinned, change `messages.aiNotice.host` and the version prefix in `config.ts` together. The notice's deletion promise reads «så snart svaret er skrevet» while `AI_RETENTION_DAYS` is unset, and «senest etter N dager» when it is set. The wording check against these terms is row 1 in `docs/qa/ai-notice-manual-checks.md`. The PRD §8.1 data rules are not changed by Story 3.6 (see `deferred-work.md`).
