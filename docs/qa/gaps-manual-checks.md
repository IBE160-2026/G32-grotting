# Gap analysis: manual checks on one live Fixture run (FR-13, FR-14)

Story 4.6 (FR-13, FR-14, NFR-1). The automated tests prove the Gaps route and its structure step, the citation check (FR-15), the Cached Gaps for every Fixture, the «Gapanalyse» section on Søknad, the Letter check with Gaps, and the default-on flag with Hosted forced off (`src/shared/server/config.test.ts`, `src/modules/gaps/**/*.test.ts`, `test/cached-gaps.test.ts`, `test/gaps-test-mode.test.ts`, `e2e/gaps.spec.ts`). What only a person can judge is recorded here: whether the Gaps the AI writes are honest and well worded. This is checklist §9.2 items G1, G2, G3 and G5 in the PRD. **A row is a result only when the Date, Tester and Result columns are filled in. A blank Result means open, not passed.**

How to run: one live run on one Fixture with a real key (`AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY` in `.env`), then read the Gaps on screen next to the Fixture's Answer key. For G2, save the live answers in a folder and run `npm run qa:compare -- --dir <mappe>` on those fresh answers; the Cached Gaps are not a live result. A failure leads to a prompt fix and a new `PROMPT_VERSION` (and a new recording of the Cached Gaps), never to a looser citation check.
