# Rewording suggestions: the first live checklist run (FR-16, FR-17, SM-3, SM-5)

Story 5.4 (FR-16, FR-17, SM-3, SM-5, PRD §9.2, the decision point of 3 December). The automated tests prove the suggestion step in the Gaps route, the FR-17 guard (a Missing keyword other than the Gap's own, an Upgrade word the cited CV entry lacks, the planted cases in `data/fixtures/_planted/`), the Cached Gaps with a suggestion for every Rewordable gap, the suggestion box and «Kopier» on Søknad, the default-on flag with Hosted forced off, and the G2 and G4 counts of `qa-compare` (`src/modules/integrity/core/check-suggestion.test.ts`, `src/modules/gaps/**/*.test.ts`, `src/app/api/analyses/[id]/gaps/route.test.ts`, `src/shared/server/config.test.ts`, `test/cached-gaps.test.ts`, `test/gaps-test-mode.test.ts`, `scripts/qa-compare.test.ts`, `e2e/suggestions.spec.ts`). What only a person can judge is recorded here: whether the live Letter, the Gaps and the suggestions are honest and well worded. This is the whole checklist §9.2 in the PRD: L1–L8, G1–G5 and R1–R3. **A row is a result only when the Date, Tester and Result columns are filled in. A blank Result, or «ikke kjørt», means open, not passed.** No row in this file has been run, and no live run was made by the build.

How to run (Helene, with a real key; no live run was made by the build):

1. Put `AI_PROVIDER`, `AI_MODEL` and `AI_API_KEY` in `.env` (no `TEST_MODE=true`, and no `FEATURE_REWORDING=false`, which would switch the suggestions off), start the app (`docker compose up`) and run **every Fixture live**: «Bruk eksempelet» for the Example pair, and the CV and Job ad of each of the other Fixtures (`data/fixtures/<fixture-id>/cv.txt`, `ad.txt`). Check that each Rewordable gap shows its suggestion box. Read each output on screen next to the Fixture's `answer-key.json`. Every live run is a paid request; no run was made by the build.
2. Get the **raw** live Gaps answer of each Fixture: the Gaps route only returns the answer after the structure step and the FR-15 and FR-17 checks, so use the recorder, `npm run fixtures:record -- <fixture-id> --gaps` (one request per Fixture; it reads `cached/keywords.json`). It writes `data/fixtures/<fixture-id>/cached/gaps.json`. Copy that file to `<mappe>/<fixture-id>/gaps.json`, and restore the committed one with `git restore data/fixtures/<fixture-id>/cached/gaps.json` unless the run is the re-recording after a prompt fix (step 5). For L1–L8, record the Letter the same way (`--tone Formell|Personlig|Direkte`, written to `cached/letter-<tone>.json`) or read it on screen; `qa:compare` reads only `gaps.json`, so L2, L3 and L7 are read by hand. Run `npm run qa:compare -- --dir <mappe>`. It reports every G2 failure (a must-never-suggest keyword that became Rewordable) and the **G4 count** (how many of the Answer keys' expected Rewordable gaps were found and shown with a suggestion that passed FR-17, counted across all Fixtures; the target in SM-5 is at least 70 %). The Cached Gaps are not a live result, and `qa:compare` without `--dir` reads them.
3. **Commit the live outputs next to the results** (PRD §9.2, §9.4), for example under `docs/qa/rewording-live-runs/<date>/run-<n>/<fixture-id>/`, together with the output of `qa:compare`. Check first that the files hold no key or other setting (the recorder writes only the answer and its `meta`).
4. Fill in Date, Tester and Result per row. For the final prompt version, record 3 live runs per Fixture and check each one (SM-3): one `<mappe>` per run (`run-1`, `run-2`, `run-3`), `qa:compare` once per folder, and each run's G2 and G4 lines kept in the Result column.
5. **A failure on L2, G1, G2 or R1 leads to a prompt fix, a new `PROMPT_VERSION`, a new recording of the Cached Gaps (`npm run fixtures:record -- <fixture-id> --gaps`, and the Letter's recording if the Letter prompt changed; a failure on G3, G5, R2 or R3 or a G4 below 70 % is written in the Result column and decided by the product owner) and a new run of the Fixture.** It never leads to a looser `canonVerbatim`, `checkCitation` or FR-17 check, and never to an edited Answer key. Write the failure and the fix in the Result column.
