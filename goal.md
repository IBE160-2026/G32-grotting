- Rekkefølge: 5.1, 5.2, 5.3, 5.4. 5.2 og 5.3 bygger på `suggestion`-feltet fra 5.1, 5.3 på FR-17-steget fra 5.2, og 5.4 kommer sist og slår flagget på. Til 5.4 er `FEATURE_REWORDING` av som standard, og testene setter det på eksplisitt. Ikke slå det på i `FEATURE_DEFAULTS`, `compose.yaml`, `.env.example` eller README før 5.4. Med flagget av er hver `suggestion` fortsatt `null`, som i Epic 4.
- Kjør `npm test` og `npm run typecheck`. Rører storyen `package.json`, lockfila, `Dockerfile` eller `data/` (gjelder 5.1 og 5.2), kjør også `docker compose run --rm --build test`; den er done-kriteriet. Playwright-testene i 5.3 og 5.4 er en del av `npm test`.
- Push, åpne PR, og merge når `ci` er grønn. Har `ci` feilet, rett og push på nytt. Maks 3 forsøk, deretter stopp og skriv det til `.logs/helise-26/issues.md`.
- Etter hver merge: oppdater `sprint-status.yaml` (se under for `epic-5`), bruk `sesjonslogg` (logg + `issues.md`, commit), og gå til neste story fra `main`.

Regler til underagenten (ta dem ordrett inn i prompten for hver story):

- Aldri kjør `git checkout -- .`, `git reset --hard` eller andre kommandoer som kaster uncommittede endringer. I 4.4 gikk uncommittede endringer tapt slik.
- Underagenten kjører ikke `sesjonslogg` og skriver eller committer ingen fil i `.logs/`. Det gjør hovedløkka. Er den blokkert, kan den legge en ukommittet linje i `.logs/helise-26/issues.md`.
- `sprint-status.yaml` (storyen satt til `done`) ligger i samme PR som storyen, ikke i en oppfølger-PR. `epic-5` settes til `in-progress` i PR-en til 5.1 og står der også etter 5.4 (retroen er Helenes).
- Underagenten venter til `ci` er ferdig (`gh pr checks --watch`) før den merger og før den svarer. Den kommer ikke tilbake mens `ci` fortsatt kjører.
- Reviewlagene i `bmad-build-auto` kjøres ikke i bakgrunnen: vent på alle fire før triage.
- Gjennomgå en prompt før den spilles inn (5.1): `gaps-1` måtte endres etter lesing, ikke etter testene. Innspillingen er siste implementasjonssteg, ikke noe reviewlagene kan be om å gjøre om.
